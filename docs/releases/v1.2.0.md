# v1.2.0

- New RSS, backfill and manual tasks download directly to their destination. Optional renaming keeps torrent directories and attachments in place; no staging, backup, attachment folders, moves, replacement or cleanup.
- Backfill confirms downloads only. Duplicate downloads use PikPak's automatic filename suffixes. Rename collisions are handled by PikPak; rejected renames retain the current filename for review.
- Persist task/file IDs and rename progress, read back actual filenames, and resume after restart without repeating uncertain submissions or renames.
- Existing jobs retain their staged workflow, persisted IDs, replacement backups and cleanup ownership. SQLite remains schema 4; the new job mode and actual filenames are stored in existing JSON payloads.

Back up the complete data volume, then run `docker compose pull` and `docker compose up -d`, or pin `ghcr.io/wade00754/pikpak-rss-manager:v1.2.0`. Do not downgrade with direct jobs in the current database; restore a pre-upgrade backup instead.

[Verification](https://github.com/wade00754/pikpak-rss-manager/blob/main/docs/verification.md) records checks and release evidence.
